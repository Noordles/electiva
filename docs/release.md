# Review candidate and submission gate

The release bundle contains the committed JavaScript source, tests, lockfile, environment example, preserved requirements, design/architecture/security/setup documentation and measured evidence. It excludes dependencies, Git metadata, .env secrets, runtime databases/WAL files, demo credentials and cached browser binaries. The generated archive is kept outside the checkout under the subject's deliverables folder, with its commit and SHA256 receipt.

Technical verification is separate from final college acceptance. Before the student uploads:

- Inspect the final CI/local verification, CON crash/recovery evidence, actual performance results and clean setup receipt.
- Each member completes their own inspection and significant AI-assisted case in docs/defense and contributions.md. Planned ownership and prepared worksheets do not establish participation. Verify real teammate identities before any actual teammate-authored commit/review credit.
- Confirm teacher acceptance of the separate directory simulator, the final version of the Draft v2.0 requirements and actual milestone dates. None is inferred from a sent request or this repository.
- Rehearse the proposed demo with all three members, including explaining the transaction and measured limitations. The speaking plan is ready; group rehearsal is not claimed.
- The student personally chooses and uploads the archive. The agent does not submit, contact the teacher, mark attendance, register a team or expose the repository publicly.

No required failing behavior is hidden by claiming a load timeout is a successful enrollment or that the highest tested user count is universally sustainable. Overload failures and resource stops remain in the saved datasets. The short repeated comparison is a classroom experiment with explicitly recorded limits.
